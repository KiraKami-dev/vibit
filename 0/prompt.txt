### scenario.py (972 lines): the seeded world generator

- **Entry point:** `generate(seed: int, dataset: str = "mixed") -&gt; World` (l.335). It tries up to 200 sub-seeds, `random.Random(seed * 1009 + attempt + salt)` with `salt = index(dataset) * 7_000_003`, and returns the first draw the oracle accepts as unambiguous and whose decision matches the `no_bid` flag (l.969-971).
- **`_generate(seed, r, fixed) -&gt; World`** (l.347) imports `oracle` to place traps around true values, e.g. a threshold one cent above the order value or a ceiling one piece short.
- **`profile(dataset, seed) -&gt; dict`** (l.281) returns the features a dataset pins; everything else is drawn.
- **`GENERATION = 3`** (l.21) is recorded with each run; a seed means a different scenario across generations.
- **Dataclasses** (l.61-189): `Position`, `QA` (kinds: quantity, withdrawal, group, packaging, commitment, pool, bonus, setup, amendment, noise), `Req`, `Revision` (status current/superseded/draft/withdrawn), `Condition`, `Material`, `Mail` (`kind`, `reference`, `is_record`, `data`), `Tender`, `World` (with `senders()` and `current()`).
- **Number formatting:** `de(value, places=2)` and `plain(value)` (l.44, l.55) read a module-global `LOCALE[0]`, mutated per mail in `versions.send` (l.643). This is not thread-safe.

How many scenarios: unlimited seeds across 33 named datasets (`DATASETS`, l.244-278).

- `mixed`: every feature drawn at random.
- `public-like` and `no-bid`: every rule in play on five positions.
- `plain`: no clauses at all.
- `one-trap`: `TRAPS[seed % 22]` (l.232-243), one rule's trap on an otherwise plain tender.
- 28 single-oddness sets, e.g. `boundaries-met`, `boundaries-missed`, `minute-precision`, `long-chains`, `decoy-flood`, `only-fakes`, `many-revisions`, `release-taken-back`, `strange-ids`, `foreign-notations`, `metal-maze`, `everything-weird`.

What varies in the data:

- **Feature flags** (l.350-359): `no_bid` 15 %, `satz`, `shared`, `usable`, `amend`, `withdrawn`, `fx`, `unit100`, `approval` in none/plain/cond_pass/cond_fail, `groups`, `metal`, `windows`, `packaging`, `commitment` in none/applies/ceiling/material, `pool` in none/largest_remainder/rest_to_largest, `bonus`, `setup`.
- **Surface forms** (l.362): `opaque_ids`, `tight_dates` (hours apart, or `"minutes"`), `small_quantities`.
- **Identity:** scenario date 2025-2027, reference formats (`_reference`, l.195), company and domain (`*.example`), director, mailbox local part.
- **Structure:** 3-5 positions (1, 8 or 12 in some datasets), position-number schemes, requirement-id schemes, revision naming (letters, 01.., 2.0.., roman, opaque `R-1234`), 2-3 revisions plus optional withdrawn and draft ones.
- **ERP:** material-number schemes (`_material_number`, l.204), catalogue-group schemes, 7-10 extra groups so a broad search is refused.
- **Mail:** 10-16 noise mails (40-60 in flood), inbox/archive split (l.954), per-mail number notation de/en (ch/fr in some datasets) declared in the body (l.644).

### sites.py (821 lines): four mock sites

- **Framework:** stdlib `http.server.ThreadingHTTPServer`, one server per site on 127.0.0.1.
- **Ports:** `start(app, first_port=0) -&gt; list[ThreadingHTTPServer]` (l.811) uses free ports by default; `serve --port 8800` uses 8800-8803. It sets `site.url`.
- **Classes:** `App(world)` (l.120) holds `skin`, `signed`, `tans`, `tan_mails`, `hits` and `clock()` (the scenario clock). `Site` (l.150) is the base for `TenderSite`, `SupplierSite`, `ErpSite`, `MailSite`. `Handler` (l.772) uses a cookie `sid_&lt;role&gt;`.
- **Look:** `Skin(random.Random((world.seed + 1) * 7919))` (l.67-88) depends on the seed only, not the dataset. It draws:
  - paging (next/numbered/more) and page size 4-6;
  - list style (table/cards) and date notation (de/iso/UTC+2 offset);
  - bid-form flow (wizard, wizard_each, single) and material input (text/select);
  - revision status display (badge/tooltip/text) and spec style (table/prose);
  - ERP layout (tabs/sections) and mail opening (page/pane);
  - `qa_site` (tender, tender, supplier) and `qa_order`;
  - default offer type (`neben` or empty), confirm dialog, empty-search behaviour;
  - hazards, each at 60 %: flaky, timeout, modal, inject, gate;
  - brief headings, one of two German label vocabularies (`WORDS`, l.47), and product name plus site id per role from 4 options (`PRODUCTS`, l.37), including neutral `site-1`..`site-4`.
- **Login and nuisances** (`Site.dispatch`, l.217):
  - `/login` POST with per-process random credentials (`secrets`, l.156, not seeded).
  - `/consent` cookie wall.
  - `/zugang` access-number gate on supplier and ERP.
  - ERP session expiry after 40 hits (l.264).
  - A flaky page on hits 5 and 23 (l.267).
  - A newsletter overlay.
  - A hidden prompt-injection div in mails (l.729).
- **Tender routes:** `/` (search, 3 per page, 4 decoy tenders), `/a/&lt;tid&gt;`, `/a/&lt;tid&gt;/unterlagen[/1..3]` (1 is the bill of quantities), `/a/&lt;tid&gt;/fragen` (only if `qa_site == "tender"`), `/a/&lt;tid&gt;/angebot?schritt=N`, `/a/&lt;tid&gt;/angebot/pruefen` with `aktion=tan|abgeben`.
- **Supplier routes:** `/` (document search), `/dok/&lt;id&gt;?rev=` (opens `revisions[0]`, the oldest, l.607; requirements 2 per page), `/klarstellungen[/&lt;tid&gt;]` when the Q&amp;A lives there.
- **ERP routes:** `/suche?q=` (empty refused, more than 20 hits refused, l.661), `/material/&lt;nr&gt;?tab=technik|dispo|bestand|logistik|preise`.
- **Mail routes:** `/?ordner=inbox|archive&amp;q=` (AND search, per folder), `/nachricht/&lt;mid&gt;` or pane `?nachricht=`.

- **TAN:** `secrets.token_hex(4).upper()`, valid 5 minutes, each request invalidates earlier ones, delivered as a mail in the inbox (l.515-525). The signed bid is stored in `App.signed`; there is no HTTP back door.

How ids and URLs reach the agent: only through the run JSON built by `run.py` (`access[].siteId/url/credentials`, shuffled) and the brief's shuffled site list.

### oracle.py (412 lines): independent answer, scorer, calc cross-check

- **Record selection:**
  - `authority(world, kind)` (l.34): latest record with exact reference, authorised sender, `date &lt;= scenario`.
  - `entry(world, kind, **where)`.
  - `qa_key(world, kind, position)`.
- **Per-position derivation:**
  - `quantity` (rules 1, 13).
  - `pieces` (17).
  - `requirement` (2, 14, 20).
  - `material` (3, 10; raises on two matches).
  - `base_price` (4, 22).
- **Order level:**
  - `order_value` (16).
  - `discount(world, value)` (5, 16).
  - `split_cents(amount, weights, rule="largest_remainder")` (l.136).
- **`solve(world, detail=False) -&gt; dict`** (l.156):
  - Any missing material gives no_bid; the discount is the plain approval's percent, or 0 if the approval is conditional.
  - Otherwise unit price is `base*f_base + surcharge*f_sur + (setup + cartons - credit)/count`, rounded once (l.220).
  - Lead time uses pooled demand against free stock, then a commitment override (l.221-226).
- **`score(world, expected, got) -&gt; dict`** (l.255): rule 29 weights, positions matched by number, extras cost one position's share. No-bid cases score 75/5/5/15.
- **`via_calc(world) -&gt; dict`** (l.327) feeds the same world through `agent/calc.py`.

Two caveats in the scorer:
- The docstring cites `docs/scoring.md`, which does not exist on the branch.
- The two "when present" 5-point checks are the author's interpretation (l.7-9): the quantity of the position behind a withdrawn answer, and the surcharge of positions with windowed indices.

### run.py (436 lines): the CLI

| Subcommand | What it does |
| --- | --- |
| `check --seeds 300 --first 0 --forms 60` | Compares oracle with `via_calc`; does an HTTP form round trip via `Client`/`enter()` (l.127-179) that must score 100 |
| `show --seed N` | Prints features, look and expected answer |
| `serve --seed N --port 8800` | Serves the sites, writes `dev/synth/.run-N.json`, prints the score when a bid is signed |
| `agent --seeds 0-5 --minutes 20 --version --note` | Runs the agent per seed and records the score |
| `export --seeds --out` | Writes plain JSON per scenario including labels and expected answer to `dev/synth/data/` |
| `report --version` | Mean quality by feature and look, most frequent misses |

All except `report` take `--dataset`.

How it stands in for the platform:

- **Brief:** `brief(app)` (l.52) is an English task brief with reference, scenario time, company, VAT, director and shuffled site list, followed by `rules.md` verbatim and submission instructions.
- **Run object:** `build_run(app, seconds=1200)` (l.94) returns `{run_id: None, brief, access, submission: {kind: "site", siteId, url}, answer_schema, started_at, expires_at}`.
- **No API server:** the run is passed only as `CHALLENGE_SCOUTING`. There is no `/v1/runs/current`, no run token, no `llm_proxy_url`.
- **No schema validation:** `answer_schema.json` is only handed to the agent; the bid form's `collect()` is the sole validation.
- **Scoring:** `judge(app, expected)` (l.106) calls `oracle.score` on `App.signed`, turns an alternative offer into a wrong decision, and reports form traps (own terms, omitted, extra rows, TAN requests, company and contact correctness) and seconds.

How it drives the agent (`run_agent`, l.326-358):

- It runs `subprocess.run(["uv", "run", "--no-sync", "python", "agent.py"], cwd=ROOT/"agent", ...)` with timeout minutes*60+120.
- It removes `CHALLENGE_RUN_TOKEN` and `CHALLENGE_API_URL` from the environment.
- It sets `CHALLENGE_SCOUTING`, `TRACE_DIR=agent/traces/synth-&lt;seed&gt;-&lt;ts&gt;`, `HEADLESS` (default 1), `NO_PROXY`/`no_proxy`, and defaults `QWEN_BASE_URL=http://127.0.0.1:8765/qwen/v1`, `QWEN_API_KEY=local`.
- It appends a record to `experiments/synth-runs.jsonl`: quality, parts, wrong fields, features, look, request counts, commit, dirty flag, and any `AGENT_|LLM_|THINKING|MAX_STEPS|SPEC_` variables.
- `cmd_agent` first probes the model proxy (l.363).

`rules.md` (29 lines) is identical to the 29 rules in the live `rfq.md`. `answer_schema.json` matches the live schema.
