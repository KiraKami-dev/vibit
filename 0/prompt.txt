## Design
**`agent/browser_tools.py` (`SiteSession`)**
- **Same tab:** one attempt has a 210 s budget (`SESSION_START_SECONDS`). It runs goto for up to 60 s and does not abort the request if that times out. It then loops settle (45 s cap) and look (30 s cap) on the same tab until the page shows something. Only a closed tab, the browser's own error page or the budget ends an attempt. If the budget runs out while the page shows something (e.g. a sign-in still pending), it returns that page rather than failing.
- **Pending sign-in:** if the sign-in form is still showing within 45 s of sending it on the same URL, the helper does not send it again; the start keeps waiting. Before, sending it again could cancel the post-login page that was still loading.
- **Retries:** after a failed attempt it waits 30, 60, then 120 s (repeating) before trying again. It keeps going until `until`; by default that is 300 s before the run's deadline (`browser_tools.DEADLINE`, set by `agent.solve`). `until` can be changed while a start is running.
- **Fresh context:** the third attempt runs in a new browser context. If that also fails, the session goes back to the original context and closes the new one.
- **Pending starts:** `revive()` waits for a start that is still running in another task instead of opening a second tab. So a session can be handed to a worker or to `submit_bid` before it is up.
- `_goto` now allows 60 s instead of 30 s.

**`agent/agent.py`**
- A new `warm_up()` starts all sign-ins as background tasks and returns at once, so the brief model call no longer waits for them.
- The bid site from the run contract keeps warming until 300 s before the deadline. Other sites give up after 600 s; the mail site is moved up to the long limit once the brief names it.
- The second pair of start attempts before research is gone. A trace event `starts state` records each site's state when research ends.

**`agent/orchestrator.py`**
- The orchestrator receives the warm sessions. A new `site_up(site)` makes each worker on a site (tender, qa, spec, mail tabs) wait for that site's warm session, then join, while workers on sites that are already up carry on.
- Worker starts retry until the research deadline.
- ERP tabs that `research.py` opens itself don't wait for their site; they only get the longer default retries.
